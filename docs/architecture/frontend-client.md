# Component: Open Frontier frontend preview

- **Status:** Implemented for the frontend preview; Firebase code is not live-verified and requires owner configuration.
- **Owner/task:** TASK-003 frontend; TASK-001-CORRECTION.
- **Purpose:** A responsive frontend prototype demonstrating the Open Frontier landing page, chat, sign-in, wallet/rewards, and account/settings screens. Sign-in uses Nanoware's existing Firebase Authentication project; Supabase remains the database client, and other preview functions do not constitute production services.
- **Responsibilities:** Present all five user-facing routes; show clear preview notices; provide responsive local navigation; start sign-in through Firebase's existing Google provider; restore Firebase local persistence, refresh ID tokens, and support sign-out; pass Firebase tokens to Supabase through `accessToken`; keep chat, wallet, and rewards preview behavior distinct from live services.
- **Inputs/outputs:** Firebase Web App configuration is read from `NEXT_PUBLIC_FIREBASE_*`; existing Supabase URL and public key remain in `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`. `GET /api/auth/session` and protected API routes verify a Firebase bearer token and use Firebase UID as identity. There is no Supabase cookie session or OAuth callback.
- **Dependencies:** Next.js/React/TypeScript scaffold chosen for this authorized prototype, but ADR-0002 remains Proposed and founder approval is still required before treating this as the approved launch stack. API shapes are derived from `docs/api/proposed-contracts.md`, which remains Proposed and unimplemented.
- **Failure and retry behavior:** Firebase provider cancellation, missing configuration, unavailable sign-in, and missing `role: authenticated` claims produce safe UI errors. Firebase restores persisted user state and refreshes ID tokens. Live provider behavior remains unverified until the owner configures the existing project and tests a non-production deployment.
- **Security/privacy considerations:** Server API authorization verifies Firebase JWT signature, project issuer/audience, expiry, subject, auth time, and the required role claim. Firebase UID, never client-supplied IDs or email, keys API ownership. Supabase retains database responsibilities and existing RLS; no service-role key is used. No Firebase private key or Google client secret is in browser code. Profile provisioning is blocked because no real Supabase profile/wallet schema or migrations exist in this repository. The preview balance and mock content remain non-real; see `docs/security/README.md`.
- **Observability:** No production telemetry, audit logs, or server persistence. Preview-only status labels are visible in the interface.
- **Implementation location:** `app/api/auth/`, `app/sign-in/`, `components/nanoware-auth.tsx`, `lib/firebase/`, `lib/supabase/client.ts`, and `lib/server/firebase-id-token.ts`.
- **Related ADRs:** [ADR-0002](../decisions/ADR-0002-launch-technology.md) (Proposed); [ADR-0004](../decisions/ADR-0004-identity-and-abuse.md) (Proposed); [ADR-0005](../decisions/ADR-0005-monetization-integrations.md) (Proposed).
