# Component: Open Frontier frontend preview

- **Status:** Implemented for the frontend preview; TASK-001 Google OAuth code is implemented but not live-verified.
- **Owner/task:** TASK-003 frontend; TASK-001 Google OAuth.
- **Purpose:** A responsive frontend prototype demonstrating the Open Frontier landing page, chat, sign-in, wallet/rewards, and account/settings screens. The sign-in UI starts Google OAuth through Supabase Auth when configured; other preview functions and proposed backend contracts do not constitute production services.
- **Responsibilities:** Present all five user-facing routes; show clear preview notices; provide responsive local navigation, keyboard-operable account tabs, and visible focus indicators; start Google OAuth through Supabase Auth and exchange the PKCE callback server-side; keep email/password, chat, wallet, and rewards preview behavior explicitly distinct from live services.
- **Inputs/outputs:** Google OAuth uses `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`, redirects through `/auth/callback`, and exposes verified cookie-backed identity through `GET /api/auth/session`. Other preview content continues to use the existing local mock adapter and is not a live backend.
- **Dependencies:** Next.js/React/TypeScript scaffold chosen for this authorized prototype, but ADR-0002 remains Proposed and founder approval is still required before treating this as the approved launch stack. API shapes are derived from `docs/api/proposed-contracts.md`, which remains Proposed and unimplemented.
- **Failure and retry behavior:** Google provider cancellation, missing authorization code, callback exchange failures, and missing Supabase configuration return generic error messages. Initiation is guarded against duplicate clicks. Live provider failure, refresh, logout, and expiry behavior still needs verification with an owner-configured non-production project.
- **Security/privacy considerations:** The callback exchanges codes server-side through Supabase SSR cookies, uses `auth.getUser()` for verified session reads, and allows only `/`, `/chat`, `/settings`, and `/wallet` as post-login destinations. No Google secret is in browser code. The preview's sample balance, ledger, and mock content remain non-real; balance/reward security requirements remain Proposed in `docs/security/README.md`.
- **Observability:** No production telemetry, audit logs, or server persistence. Preview-only status labels are visible in the interface.
- **Implementation location:** `app/auth/`, `app/api/auth/`, `app/sign-in/`, `components/`, `lib/supabase/`, and `lib/server/oauth-callback.ts`.
- **Related ADRs:** [ADR-0002](../decisions/ADR-0002-launch-technology.md) (Proposed); [ADR-0004](../decisions/ADR-0004-identity-and-abuse.md) (Proposed); [ADR-0005](../decisions/ADR-0005-monetization-integrations.md) (Proposed).
